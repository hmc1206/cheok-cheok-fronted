# 척척 프로젝트 컨텍스트

> 기준일: 2026-08-16
>
> 제품 요약과 최신 통합 API 명세(v2.0, 2026-08-08)를 프론트엔드 작업용으로 정리한 문서다.
>
> 문서 충돌 시 최신 통합 명세와 그 안의 더 최근 날짜 메모를 우선한다.

- **기준 저장소**: `https://github.com/hmc1206/cheok-cheok-fronted.git`
- **기술 구성**: React 19 + Vite 8 프론트엔드

## 핵심 요약

1. **척척**은 어르신의 음성 요청을 이해해 앱 실행 또는 화면 단계별 안내로 연결하는 시니어 음성 생활 도우미다.
2. 단순 앱 연결을 넘어, 자동 실행이 불가능한 과업(예매·키오스크 등)을 단계별로 안내해 과업 완료율을 높이는 것이 핵심 가치다.
3. 기존 개발 구조인 **Spring Boot Intent Router + React 프론트엔드**와 정합성을 유지한다.

## 1. 제품 개요

- **한 줄 정의**: 시니어 음성 생활 도우미
- **제품 목표**: 음성 요청 → 의도 파악 → 앱 실행 또는 다음 행동 안내로 스마트폰 과업 해결
- **배경**: 어르신은 앱 탐색과 다단계 화면 조작에 어려움을 겪기 쉬우며, 음성 기반 안내로 이를 완화한다.
- **카테고리**: 라이프스타일 / 일상
- **사용자 역할**: 어르신 사용자, 보호자·돌보미
- **주 사용 기기**: 안드로이드 스마트폰. API 계약은 iOS·Android·Web 공통을 고려한다.

## 2. 문제와 해결 방식

- **사용자 문제**: 앱 탐색과 다단계 조작의 어려움이 과업 포기 또는 타인의 도움 요청으로 이어진다.
- **해결 방식**: 음성 요청을 의도로 분류하고, 즉시 실행 가능한 것은 자동 연결하며, 자동 처리가 불가능한 것은 현재 화면 기준의 다음 행동을 음성과 화면으로 안내한다.
- **차별점**: 느린 말투, 반복, 사투리, 불완전 문장에 대응하며 단순 연결을 넘어 단계별 행동 안내까지 제공한다.

## 3. 주요 사용자와 시나리오

- **주 사용자**: 통화·문자는 가능하지만 앱 검색, 설정, 다단계 조작은 부담스러운 60대 이상 어르신
- **보조 사용자**: 가족과 돌봄 제공자
- **시나리오 A**: “유튜브에서 가요 틀어줘” → 결과 확인 → 유튜브 앱 또는 웹으로 연결
- **시나리오 B**: “KTX 표 예매하고 싶어” → 목적지·날짜 등 필요한 정보 확인 → 역까지 이동 및 예매 화면의 단계별 안내

## 4. 성공 지표와 리스크

### 성공 지표

- 의도 파악 성공률
- 앱 실행 성공률
- 기능 연결 성공률
- 단계 안내 후 과업 완료율
- 재질문 후 해결률

### 주요 리스크

- 음성 인식 오류로 인한 신뢰도 하락
- 외부 앱 정책 변경에 따른 실행 범위 제한
- 결제·예약 등 민감 행동의 오작동과 개인정보 노출
- 피싱·사기 가능성이 있는 앱 또는 사이트 연결

## 5. UX 및 안전 원칙

- 문장과 선택지는 어르신이 이해하기 쉬운 표현을 사용한다.
- 음성 재입력보다 **큰 `quickReplies` 버튼**을 우선한다.
- 자유 형식 입력을 요구하기보다 제한된 선택지나 재발화를 제공한다.
- `ttsText`는 화면 표시와 함께 즉시 읽어준다.
- 의도 신뢰도가 낮거나 민감 행동이면 확인 단계를 생략하지 않는다.
- 결제·주문·예약의 최종 확정은 반드시 사용자가 직접 수행한다.
- 외부 앱 내부 절차를 자동 조작하지 않는다.
- 허용 목록 밖의 앱과 사이트는 차단하고 안전한 설명을 제공한다.
- 개인정보와 권한은 필요한 범위만 요청하며, 거부 시 허용 방법이나 안전한 대안을 안내한다.

## 6. 기능 명세

### 6.1 인식 요청 결과 확인

- 음성 요청을 이해한 결과를 쉬운 문장으로 사용자에게 확인한다.
- 맞으면 다음 처리를 진행하고, 다르면 재발화로 수정한다.
- 앱 실행과 세부 질문은 별도 단계에서 처리한다.

**예외 처리**

- STT 결과가 공백 또는 무음이면 “잘 못 들었어요”를 재생하고 재시도를 유도한다.
- 사투리나 불완전 문장으로 의도 신뢰도가 낮으면 확인 질문을 반드시 거친다.

### 6.2 앱 및 생활 과업 연결

- 요청에 맞는 대상 앱을 실행하거나 관련 기능으로 연결한다.
- 유튜브 재생, 지도 검색처럼 연결 가능한 과업을 우선 지원한다.
- 외부 앱 내부 절차의 자동 조작은 범위 밖이다.

**예외 처리**

- 대상 앱이 없으면 웹 폴백을 사용하고, 필요하면 설치 안내 또는 대체 앱을 제안한다.
- 권한 거부 상태면 권한 허용 방법을 화면으로 안내한다.
- 같은 의도에 복수 앱 후보가 있으면 사용 이력 또는 기본 앱 기준의 우선순위 정책이 필요하다.

### 6.3 음성 대화 재확인

- 정보가 부족하거나 의도가 중의적이면 쉬운 말로 추가 정보를 확인한다.
- 선택지 또는 재발화로 응답하게 하고 자유 형식 입력을 강요하지 않는다.

**예외 처리**

- 무응답 세션 타임아웃 처리 방식을 제공한다.
- 재질문은 최대 3회를 기준으로 하며, 이후 터치 입력이나 보호자 도움 등 대체 안내로 전환한다.
- 선택지 밖의 답변이 오면 선택 가능한 답을 다시 안내한다.

### 6.4 단계별 사용 안내

- 자동 처리가 불가능한 과업은 화면과 음성으로 한 단계씩 안내한다.
- 키오스크와 KTX 예매 등 다단계 조작 과업을 대상으로 한다.
- 결제와 예약의 최종 확정은 사용자가 직접 수행한다.

**예외 처리**

- 안내 중 다른 요청이 들어오면 현재 안내를 중단할지 확인한다.
- 앱 전환이나 종료로 세션이 유실되면 이어하기 복구를 고려한다.
- 결제·예약 중 이탈 시 임시 입력값 보존 여부는 별도 정책으로 확정한다.

### 6.5 안전한 외부 앱 사용

- 외부 앱 연결과 민감 행동에서 개인정보와 사용자의 실제 의도를 보호한다.
- 앱 접근 권한, 연결 대상, 결제·예약 직전 확인을 포함한다.
- 외부 서비스 자체의 보안 정책은 범위 밖이다.

**예외 처리**

- 보호자 동의 또는 알림 연동은 별도 정책으로 확정한다.
- 허용 목록 밖의 앱과 사이트는 피싱·사기 위험 때문에 차단한다.
- 권한 거부 상태의 민감 기능 요청에는 안전한 거절 메시지를 제공한다.

### 6.6 키오스크 사용 안내

- 음식점·병원·교통시설 키오스크에서 다음 조작을 음성과 화면으로 안내한다.
- 결제와 주문의 최종 확정은 사용자가 직접 수행한다.
- 현재 키오스크 API와 화면 흐름은 미정이다.

**예외 처리**

- 각도나 조명 때문에 카메라 인식이 실패하면 재촬영 방법을 안내한다.
- 매장마다 다른 UI와 버튼 배치에 대응할 범용 안내 로직이 필요하다.
- 결제 실패나 시간 초과 시 재안내 또는 직원 호출을 제안한다.

## 7. 프론트엔드 API 계약

### 7.1 공통 사항

| 항목 | 값 |
| --- | --- |
| Base URL | `https://api.chuckchuck.com` |
| 인증 | `Authorization: Bearer {token}` |
| 요청 형식 | `Content-Type: application/json` |
| 인코딩 | UTF-8, URL 파라미터는 UTF-8 URL 인코딩 |
| 날짜·시간 | ISO 8601 |

### 7.2 유일한 대화 진입점

평상시 프론트엔드는 **`POST /voice/process`만 호출**한다. 유튜브·지도·날씨의 기능별 API는 디버깅이나 단독 재생성이 필요할 때만 직접 호출한다.

요청의 핵심 필드는 다음과 같다.

| 필드 | 설명 |
| --- | --- |
| `userId` | JWT 사용자 ID |
| `audio` | 음성 입력의 Base64 원본. 프론트에서 STT하지 않는다. |
| `text` | `quickReplies` 버튼의 `value` 또는 텍스트 입력 |
| `latitude`, `longitude` | 현재 위치가 필요한 기능에서 선택적으로 전달 |

`audio`와 `text` 중 하나는 반드시 있어야 한다.

공통 응답 봉투는 다음 필드를 사용한다.

| 필드 | 설명 |
| --- | --- |
| `intent` | 분류된 사용자 의도 |
| `step` | 현재 대화 단계, 완료 시 `DONE` |
| `slots` | 현재까지 수집된 파라미터 |
| `ttsText` | 즉시 읽어줄 문장 |
| `screen` | 라우팅할 화면 코드 |
| `quickReplies` | 큰 선택 버튼 목록 또는 `null` |
| `data` | 도메인별 결과 또는 `null` |

버튼을 누르면 해당 `value`를 `text`에 담아 같은 `/voice/process`를 다시 호출한다. 백엔드는 Redis에 `userId` 기준 대화 상태를 저장하며, 10분간 활동이 없으면 세션이 만료된다.

### 7.3 주요 의도와 실행 원칙

| 의도 | 실행 원칙 |
| --- | --- |
| `YOUTUBE_PLAY` | 미리보기와 확인 후 `app_url`, 실패 시 `web_url` |
| `YOUTUBE_SEARCH` | 검색 결과를 보여주고 선택 결과를 외부 유튜브 앱·웹으로 연결 |
| `MAP_ROUTE` | 서버는 지명을 좌표로 확정하고 네이버 지도 앱·웹 링크만 반환 |
| `SEARCH_MEDICAL` | 현재 위치 기준 병원·약국을 찾아 네이버 지도 경로로 연결 |
| `WEATHER_INFO` | 지역·날짜를 확인하고 `WEATHER_RESULT`와 쉬운 날씨 조언 반환 |
| `TRAIN_BOOKING` | 역까지의 길과 외부 예매 흐름을 안내하며 서버가 직접 예매하지 않음 |
| `KIOSK_TRAIN` | 단계별 안내 대상이나 세부 사양은 미정 |
| `UNKNOWN` | 재질문 또는 대체 입력 안내 |

### 7.4 딥링크 폴백

1. 앱 URL 실행 가능 여부를 확인한다.
2. 실행 가능하면 앱 URL을 연다.
3. 앱이 없거나 실행에 실패하면 웹 URL을 연다.

유튜브는 `app_url` / `web_url`, 네이버 지도는 `naverMapAppUrl` / `naverMapWebUrl`을 사용한다. Android 11 이상에서는 `AndroidManifest.xml`의 package visibility 설정이 없으면 설치된 앱도 찾지 못할 수 있다.

### 7.5 지도 계약의 최신 기준

- `POST /api/v1/routes/naver-link`는 기능 단독 테스트용이다.
- 프론트는 출발지와 목적지 이름만 보내고, 좌표 확정과 링크 조합은 서버가 담당한다.
- **2026-08-13 결정에 따라 응답은 `naverMapAppUrl`, `naverMapWebUrl` 두 링크를 기준으로 한다.**
- 이전 v1.0의 `resolvedStart`, `resolvedGoal` 좌표 필드는 현재 계약에 포함하지 않는다.
- `/-/train` 직접 링크는 실기기 미검증 상태이므로 검증 전 확정 기능으로 가정하지 않는다.

### 7.6 날씨 계약 상태

- `WEATHER_INFO`는 2026-08-16 기준 구현 전 협의안이다.
- 화면 코드는 `WEATHER_INPUT`, `WEATHER_RESULT`를 사용한다.
- 지역을 알 수 없고 현재 좌표도 없으면 `ASK_LOCATION`으로 질문한다.
- 외부 제공업체의 상태 코드는 `CLEAR`, `PARTLY_CLOUDY`, `CLOUDY`, `RAIN`, `RAIN_SNOW`, `SNOW`, `SHOWER`, `FOG`, `UNKNOWN`으로 정규화한다.
- 프론트엔드 계약은 최종 외부 날씨 제공업체와 독립적으로 유지한다.

## 8. 공통 오류 처리

| 코드 | 프론트 대응 |
| --- | --- |
| `INVALID_REQUEST` | 누락되거나 잘못된 입력 안내 |
| `UNAUTHORIZED` | 재로그인 유도 |
| `SESSION_EXPIRED` | 처음부터 다시 말하도록 안내 |
| `INTENT_NOT_FOUND` | 쉬운 문장으로 재질문 |
| `STT_EMPTY_INPUT` | “잘 못 들었어요” 후 재시도 |
| `MAX_RETRY_EXCEEDED` | 터치 입력 또는 보호자 도움으로 전환 |
| `APP_NOT_INSTALLED` | 웹 URL로 폴백 |
| `APP_PERMISSION_DENIED` | 권한 허용 방법 안내 |
| `UNSAFE_APP_BLOCKED` | 연결 차단과 이유 설명 |
| `GEOCODE_NOT_FOUND` | 장소 재입력 요청 |
| `GEOCODE_API_FAIL`, `EXTERNAL_API_FAIL` | 재시도 가능한 오류 화면 |
| `SESSION_INTERRUPTED` | 현재 안내 중단 여부 확인 |
| `KIOSK_VISION_FAIL` | 재촬영 안내 |
| `KIOSK_ACTION_TIMEOUT` | 재안내 또는 직원 호출 제안 |
| `INTERNAL_ERROR` | 일반 오류 안내와 안전한 복귀 |

## 9. 미확정 사항과 우선 과제

- 유튜브 딥링크를 Android/iOS 실기기에서 검증
- 네이버 지도 `appname` 등록 및 실기기 검증
- 네이버 지도 `/-/train` 링크 검증; 실패하면 대중교통 `/-/transit`로 통합
- Geocoding 캐시 정책 확정
- 지역명과 기차역 매핑 정확도 확인
- 키오스크 화면 흐름 확정 후 API 설계
- 기능별 독립 API의 응답 봉투 형식 통일
- 보호자 동의·알림 정책과 세션 복구·임시값 보존 정책 확정
- 날씨 제공업체 선정 및 `WEATHER_INFO` 구현 계약 확정
- Postman 컬렉션과 Swagger/OpenAPI 문서화

## 10. 개발 판단 기준

1. 기존 컴포넌트, 훅, 스토어, API 클라이언트를 먼저 재사용한다.
2. 현재 요구사항에 없는 추상화, 설정, 의존성, 미래용 코드는 추가하지 않는다.
3. 접근성, 안전, 데이터 손실 방지, 인증, 입력 검증은 단순화를 이유로 생략하지 않는다.
4. API 응답이 명세와 다르면 조용히 추정하지 말고 폴백 처리 또는 계약 불일치를 명시한다.
5. 비자명한 분기나 파서는 가장 작은 실행 가능한 검증을 함께 남긴다.
